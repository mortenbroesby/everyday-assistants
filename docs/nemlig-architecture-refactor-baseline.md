## 2. As-is boundaries

```text
ChatGPT host / current viewer card                 Local CLI or stdio MCP
            │ OAuth MCP, tool/resource calls                 │ local credentials
            ▼                                                 ▼
Cloudflare Worker gateway (Auth0, principal policy, admission, deadline)
            │ validated principal + sealed credential + short-lived capability
            ▼
Container HTTP /mcp → request-scoped McpServer → principal-scoped client,
                                            ProductReviewService and proposals
                   │ read-only search/list/basket     │ temporary draft edits
                   ▼                                  └→ process memory only
             NemligClient ─── read/write HTTP ─────→ Nemlig web API
                   ▲
                   └─ explicit Submit/save only: before-dispatch callback
                        → owner-scoped Durable Object operation journal
                        → atomic claim → one provider POST → independent readback
```

The [Worker](../apps/nemlig-assistant/src/cloudflare-worker.ts#L456) authenticates before forwarding to the Container, uses [principal policy](../apps/nemlig-assistant/src/principal-policy.ts#L59), and attaches controller-issued credentials plus a short-lived, per-request journal [capability](../apps/nemlig-assistant/src/cloudflare-worker.ts#L579). The Container's [HTTP route](../apps/nemlig-assistant/src/http.ts#L154) checks scope/origin/principal and decrypts credentials into per-principal contexts; `tools/call` without credentials is refused. The [internal callback](../apps/nemlig-assistant/src/local-basket-callback.ts#L146) resolves capability to owner, rejects credential headers, validates bounded commands, then reaches Durable Object storage. The journal is a write fence/receipt, **not** an editable draft database. [Service acceptance](../apps/nemlig-assistant/src/mcp.ts#L89) exposes only `find_groceries` and `show_my_basket`, distinct from family-tool authority.

The [viewer resource](../apps/nemlig-assistant/src/mcp.ts#L571) is `ui://nemlig/shell.html`; [retired URIs](../apps/nemlig-assistant/src/product-viewer-identity.ts#L9) serve inert cards for cached historical conversations. [Stdio](../apps/nemlig-assistant/src/mcp.ts#L1732) is process-local/text-capable, not the authenticated hosted path. The [CLI](../apps/nemlig-assistant/src/cli.ts#L109) independently supports login/logout, search, cart, favorites, departments, browse, `add`, and `add-many`; its basket writes still require the separate exact-authorization policy.

## 3. Supported journeys and call graph

| Journey | Entry → state/service → boundary/result |
| --- | --- |
| Search and product view | [`find_groceries`](../apps/nemlig-assistant/src/mcp.ts#L1177) → [`resolveDetailedProductSearch`](../apps/nemlig-assistant/src/product-discovery.ts) → [`NemligClient.searchProducts`](../apps/nemlig-assistant/src/client.ts#L703) / exact product hydration → [`createProductViews`](../apps/nemlig-assistant/src/product-presentation.ts) → text and view payload. Read-only; a failed search is not an empty result. [`show_my_basket`](../apps/nemlig-assistant/src/mcp.ts#L1233) separately reads [`getCart`](../apps/nemlig-assistant/src/client.ts#L938), returning actual-basket rows/totals. |
| Start exact draft | [`start_product_review`](../apps/nemlig-assistant/src/mcp.ts#L1257) with `items` (no `creation_id`) → login/account identity → [`startDirectBasket`](../apps/nemlig-assistant/src/product-review.ts#L760) → validated/hydrated exact rows in the owner's process map. No provider shopping-data write; unavailable product detail is represented, while authentication failure propagates. Result includes `draftId`/`reviewContextId` for the card. |
| Saved-list source | Same tool with exact `shopping_list_id`, or [`update_product_review_conversation`](../apps/nemlig-assistant/src/mcp.ts#L1468) `list`/`select` → [`getShoppingLists`](../apps/nemlig-assistant/src/product-review.ts#L1091) / [`loadShoppingListIntoDirectBasket`](../apps/nemlig-assistant/src/product-review.ts#L798). It reads exact source ID and account, copies rows into a fresh draft, and leaves source unchanged. No name-based target inference. |
| Edit and alternatives | Model [`update_product_review_conversation`](../apps/nemlig-assistant/src/mcp.ts#L1468) or app-only [`update_product_review`](../apps/nemlig-assistant/src/mcp.ts#L1527) → [`updateReviewTarget`](../apps/nemlig-assistant/src/mcp.ts#L806) checks owner, `draft_id`, context and active mode → [`ProductReviewService.update`](../apps/nemlig-assistant/src/product-review.ts#L2672) for add/remove/quantity/alternatives/replace/navigate. Product hydration/alternative search may read Nemlig; edits do not write basket or source list. Errors retain the last confirmed draft rather than committing partial edits. |
| Refresh, cancel, expiry | `show` returns active matching draft; [`reviewOwner`](../apps/nemlig-assistant/src/mcp.ts#L628) and [`active`](../apps/nemlig-assistant/src/product-review.ts#L571) reject stale owner/IDs. Viewer [`applyPayload`, epochs, cancellation and quantity flush](../apps/nemlig-assistant/src/picker/product-viewer.tsx#L526) control host/tool ordering; `abandon_draft` calls [`end`](../apps/nemlig-assistant/src/product-review.ts#L620). Clean drafts expire after [two hours inactivity](../apps/nemlig-assistant/src/product-review.ts#L141); protected uncertain work is retained while process lives. Container [`sleepAfter = "10m"`](../apps/nemlig-assistant/src/cloudflare-worker.ts#L172) and restart may lose process drafts sooner. The server returns an unavailable/expired error; it does not reconstruct the draft from an old card. |
| Explicit Submit | Model [`submit_product_review_conversation`](../apps/nemlig-assistant/src/mcp.ts#L1578) or app-only [`submit_product_review`](../apps/nemlig-assistant/src/mcp.ts#L1636) → owner/draft/context/reviewed payload → [`submitDirectBasket`](../apps/nemlig-assistant/src/product-review.ts#L3535). Exact positive unique rows, account, active draft, and prior receipt are checked. [`addManyToCart`](../apps/nemlig-assistant/src/client.ts#L1279) reads basket and CSRF, invokes `beforeDispatch` to write/claim a durable receipt, then sends **one** `POST /Basket/AddManyToBasket` with `addToExisting: true`; it reads basket again and verifies additive results. Completed receipt yields a read-only replay result; an attempted/uncertain one prevents a second write. Pre-dispatch failure is known not dispatched; post-claim/POST/readback uncertainty is fenced, surfaced, and requires independent inspection. |
| Optional whole-basket save | App-only [`save_basket_as_shopping_list`](../apps/nemlig-assistant/src/mcp.ts#L1682) after verified Submit → [`saveCurrentBasketAsShoppingList`](../apps/nemlig-assistant/src/product-review.ts#L3724) → journal claim → [`createShoppingListFromBasket`](../apps/nemlig-assistant/src/client.ts#L1347), one `POST /ShoppingList/CreateShoppingListFromBasket`. The result acknowledges the request and verifies basket unchanged; it **does not** establish a saved-list ID. An uncertain attempt is not retried. |
| CLI/stdio | [`cli.ts`](../apps/nemlig-assistant/src/cli.ts#L109) uses authenticated `NemligClient`; `add-many` delegates to the same client bulk method but does not use a draft or hosted journal. [`mcp.ts main`](../apps/nemlig-assistant/src/mcp.ts#L1732) serves stdio with local server defaults. Neither route is proof that a hosted ChatGPT card rendered. |

MCP [errors are converted](../apps/nemlig-assistant/src/mcp.ts#L471) to tool failures; the viewer keeps [loading/error/outcome surfaces](../apps/nemlig-assistant/src/picker/product-viewer.tsx#L740). A tool result, UI state, provider acknowledgement, durable completion, and independent readback are distinct evidence levels.

## 4. State ownership and lifetime

| State | Authority and mutation | Lifetime / restart / identity |
| --- | --- | --- |
| Catalogue, saved lists, real basket | Nemlig API via [`NemligClient`](../apps/nemlig-assistant/src/client.ts#L561). List-source and basket reads are read-only; only explicit Submit/optional save write. | Provider-owned. Exact account and list/product IDs matter; local snapshots can become stale. |
| Draft | [`ProductReviewService.drafts`](../apps/nemlig-assistant/src/product-review.ts#L371), keyed by derived owner, with account identity, draft ID and review context. | Process-local; idle target two hours, max eight admitted owners; restart/Container sleep can lose it. Protected unresolved state resists ordinary idle eviction only while the process exists. |
| Viewer/host snapshot | React [`product-viewer.tsx`](../apps/nemlig-assistant/src/picker/product-viewer.tsx#L503) stores presentation, last confirmed review, pending quantities, cancellation/selection epochs; server rechecks all write authority. | ChatGPT may cache cards and passive payloads. A visible card is not a durable draft or authorization. Retired resource URIs remain inert. |
| Principal/provider session | [Worker authentication and admission](../apps/nemlig-assistant/src/cloudflare-worker.ts#L456), [HTTP context](../apps/nemlig-assistant/src/http.ts#L154), client cookie/session state. | Per validated principal/policy/credential generation; request capability expires/revokes. Account changes abort/uncertain-fence writes. |
| Operation receipt | [Durable Object storage](../apps/nemlig-assistant/src/local-basket-storage.ts#L87), owner-scoped through [callback](../apps/nemlig-assistant/src/local-basket-callback.ts#L146). Atomic claim and completion mark dispatch/verified status. | Survives Container restart. Completed direct receipts have a two-hour retention rule; unresolved/native receipts have different retention. Persisted keys and historical records require migration evidence before removal. |

## 7. Ranked first-pass hotspots

At most five slices; each has a separate implementation issue. **None is a deletion authorization.**

1. **#321 — instruction/contract drift, highest correctness leverage.** The [packaged skill](../apps/nemlig-assistant/chatgpt-plugin-source/nemlig-shopping/skills/grocery-shopping/SKILL.md#L16), [manifest](../apps/nemlig-assistant/chatgpt-plugin-source/nemlig-shopping/plugin.json#L6) and [app skill](../apps/nemlig-assistant/.codex/skills/nemlig-basket/SKILL.md#L89) tell agents to auto-save native lists; [server instructions](../apps/nemlig-assistant/src/mcp.ts#L500) and fixed mode do not. The [`find_groceries` description](../apps/nemlig-assistant/src/mcp.ts#L1178) also names `load_saved_shopping_list`, which is absent from the registered tool inventory. **High-confidence source mismatch.** Proof: inspect packaged ZIP/current `tools/list`, update only current contract, test schema/examples, then fresh installed connector acceptance. No provider write safety change.
2. **#322 — retire proven unreachable native-list orchestration.** [`mcp.ts` routing](../apps/nemlig-assistant/src/mcp.ts#L878) has a locally unreachable branch; [`ProductReviewService`](../apps/nemlig-assistant/src/product-review.ts#L371) still combines direct draft and native create/update/transfer; [`BasketProposalService`](../apps/nemlig-assistant/src/proposals.ts#L274) remains injected. **High confidence for one branch, medium/unknown for whole services.** Proof: exact method callers, tooling, published schemas/cards, tests and journal operation history; remove in small slices with behavior characterization, retain durable receipts.
3. **#323 — review shape and viewer state.** Manual schema/type/decoder copies above can drift; [`product-viewer.tsx`](../apps/nemlig-assistant/src/picker/product-viewer.tsx#L526) holds related active/last-confirmed state, epochs, timers and error gates.
