# Nemlig Assistant 5.1.2 - Welcome

## In plain language

Fix the connection form rejecting correct Nemlig credentials before validation.

## Changes

- Use same-origin referrer policy so native browser form submissions retain
  the Origin header required by the server, without sharing referrers off-site.
- Preserve exact-origin rejection, signed expiring cookies, single-use CSRF,
  owner/principal binding and the existing credential-validation path.
- Add header/origin regressions and a loopback-only browser smoke using the
  real portal renderer, cookies and replay storage with synthetic credentials.
- No new dependencies, OAuth client, secret, provider configuration or viewer
  resource. No basket actions or automatic credential-submission retries.

## Acceptance boundaries

Local browser success is not live credential readiness. Release with MCP still
disabled; the owner must load a fresh form and explicitly submit their Nemlig
credentials before connection/provider readiness can be recorded.
