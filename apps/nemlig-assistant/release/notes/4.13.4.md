# Nemlig Assistant 4.13.4 - Anchor

## In plain language

Nemlig Assistant now treats provider authentication as a bounded, verified
connection instead of assuming that a ChatGPT OAuth session also proves that
Nemlig is reachable.

## Changes

- Re-authentication starts without stale bearer or cookie credentials and
  clears stale session and product-cache state before accepting a new session.
- Read-only provider calls may perform one bounded authentication recovery,
  while session generations prevent a late stale response from replacing a
  newer session.
- Connection status distinguishes an OAuth context, a verified Nemlig
  connection, a required reconnect, and provider unavailability.
- Documentation separates ChatGPT/Auth0 reconnect from Nemlig provider
  verification and records the remaining live acceptance steps.

Production deployment and live ChatGPT acceptance remain separate operations;
this release does not perform basket mutations.
