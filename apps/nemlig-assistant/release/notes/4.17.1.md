# Nemlig Assistant 4.17.1 - Recovery checkout and diagnostics

## In plain language

An incident recovery can check out an older accepted main commit by its exact SHA, and a failed service check retains the last bounded diagnostic across retries. The release still does not retry an uncertain deployment.

## Changes

- Fetch main history and check out the verified ancestor SHA in each protected release job, avoiding a checkout-action failure on historical recovery commits.
- Preserve the last bounded service-fixture failure boundary across retries, including typed inventory or viewer mismatches; do not expose payloads or credentials.
- Cover both cases with focused deployment and workflow tests.

This source change does not itself prove a successful production rollout or native ChatGPT rendering.
