# Nemlig Assistant 5.1.4 - Additive

## In plain language

Nemlig Assistant can only add to your real basket; it no longer offers actions that remove, replace, or clear its contents.

## Changes

- Treat app-level basket quantities as positive additions and translate them to Nemlig's absolute-quantity endpoint using a fresh basket read.
- Bind each sequential product POST to the reviewed/last verified basket snapshot; stop on detected drift, consume partial proposals, and never retry or roll back.
- Verify the requested increase and that previously observed lines were not reduced or lost before reporting success; uncertain writes are not retried.
- Remove provider basket removal, replacement, and clear operations from the MCP and CLI surfaces. Local review editing remains separate.
- Reuse an authenticated session for protected additions instead of forcing a new login before every write.
- Bootstrap Nemlig anti-forgery cookies before cold login and send the matching XSRF and same-origin Origin headers on state-changing API calls; keep the prior session cookie out of login requests.
- Use Nemlig's ordinary login flags and never silently select the website's remove/save basket decision; stop and direct the user to Nemlig.com if a separate decision is required.

## Known limitations

- Nemlig's observed endpoint sets an absolute line quantity and exposes no atomic increment or compare-and-set. Snapshot checks stop detected drift before a POST or between product writes, but another Nemlig client changing the basket after our final read and before Nemlig applies the POST can still race.
- Cold-session login behavior remains unresolved. Bounded attempts using the ordinary website flags and first-party anti-forgery/Origin headers returned HTTP 400; immediate browser readback showed no visible basket change. Source inspection shows the previous `false,false,false` tuple corresponds to the website's explicit “remove from basket” choice, but the direct backend effect is unverified. The assistant no longer sends that tuple. Successful provider login and basket-preservation acceptance remain pending.
- No checkout, delivery booking, payment, or order placement is supported by this change.
