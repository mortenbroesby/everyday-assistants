# Nemlig Assistant 5.1.0 - Doorway

## In plain language

The connection page now offers owner browser sign-in before the existing secure
Nemlig credential form. No passwords or tokens belong in ChatGPT.

## Changes

- Use the installed maintained MCP OAuth client for authorization code with
  PKCE and a POST callback; no custom Auth0 exchange or new package.
- Bind the transaction to issuer/client/state, expiry and the exact enabled
  configured owner. Consume it once through existing authenticated replay
  storage before issuing the existing protected portal session.
- Pin bounded OAuth fetches to the configured issuer origin, reject redirects
  and make at most one token exchange per callback request. A replay cannot
  issue a second portal session. No automatic retry, refresh token,
  ID-token authority, invitation/enrollment or legacy credential fallback.
- Keep credential validation/sealed replacement, CSRF, origin checks, fixed
  capacity, independent kill switches and exact basket approvals unchanged.
- Viewer resource/content and native ChatGPT review lifecycle are unchanged.

## Configuration and live acceptance

One reviewed public browser OAuth client with the exact POST callback is
required, configured as `NEMLIG_MCP_ONBOARDING_CLIENT_ID`. Provision the existing
`NEMLIG_MCP_ONBOARDING_SESSION_KEY` separately without rotating the credential
key. Preserve exact private schema-v3 owner/key/revision bindings and rollback
material. No provider/client/secret change occurs in this repository PR.

Before enabling MCP, deploy disabled, enable onboarding alone, have the owner
sign in and explicitly validate/save credentials through the existing form,
then verify live owner read-only access. Service fixtures and local OAuth tests
do not establish production owner, provider or native ChatGPT acceptance.

Each explicit sign-in adds bounded issuer discovery and one code exchange;
successful authentication adds one existing replay-storage write. App-local
quotas remain absent, so repeated authenticated activity can incur cost until
disabled. No new paid service, namespace, Container, polling or keep-warm work.
