# Nemlig Assistant 4.13.5 - Beacon

## In plain language

Nemlig Assistant now distinguishes a bad OAuth token from an unavailable Auth0
verification service, so infrastructure failures do not send users into an
unnecessary reconnect flow.

## Changes

- Auth0 discovery/JWKS timeout and transport failures return bounded sanitized
  infrastructure errors instead of OAuth reconnect challenges.
- The hosted gateway fails closed without waking or forwarding to the Container
  on authentication infrastructure failure.
- Direct HTTP authentication keeps its authenticated boundary and reports
  sanitized server errors.
- Same-principal credential-generation changes close obsolete MCP sessions;
  foreign-principal sessions remain isolated.
- Documentation records the separate diagnosis path.

No provider configuration, production deployment, or basket mutation was
performed.
