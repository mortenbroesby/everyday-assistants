# Nemlig Assistant 5.2.0 - Gather

## In plain language

Keep one shopping selection usable while people explore products, resolve
choices and prepare additions. Conversation search and Ready submission now
follow the user's stated scope more directly without weakening exact checks.

## Changes

- Keep an activated selection visible when a delayed historical card result
  arrives; correlated current-state recovery remains the only way to switch it.
- Show all unique alternatives returned when no count is requested, and allow
  deliberate follow-up searches without silently replacing the unresolved item.
- Add a 400 ms quantity quiet window with responsive totals and flush-before-
  action behavior; failed or stale quantities are not replayed or submitted.
- Preserve a prepared Ready payload through To decide-only clarification edits,
  and invalidate it whenever a Ready product or quantity changes.
- Treat a clear conversational request to add the unchanged current Ready
  selection as authorization for exactly that prepared payload. The viewer keeps
  its explicit exact confirmation; ambiguous scope still requires clarification.
- Make standalone catalogue search explicit and independent of alternatives.
  A successful empty result remains distinct from an upstream error; the
  fixture-backed HTTP 500 path retains its safe upstream status message.
- Align selection wording in the viewer and MCP catalog while retaining the
  existing 21-tool surface and protected basket write boundary.

## Acceptance boundaries

`pnpm verify`, strict OpenSpec validation, and loopback real-MCP browser smoke at
320px/375px passed using fake provider data; the smoke recorded zero provider
basket writes. Search HTTP 500 and empty-result behavior were tested with HTTP
fixtures. No live Nemlig request, real basket operation, ChatGPT refresh,
deployment, or native ChatGPT acceptance was performed. Native historical-card
acceptance remains a separate open gate.
