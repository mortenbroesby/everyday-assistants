# Nemlig Assistant 6.1.6 - Waypoint

## In plain language

This patch makes an interrupted production recovery recognize the exact
candidate it is meant to restore from, even when that candidate has a different
configuration fingerprint than the earlier accepted release. It also wakes the
Container before requiring its server package version, so a stale backend
cannot make a healthy new Container look permanently unavailable.

## Changes

- Preserve exact Worker version, source revision, Container image, and
  application-version checks during recovery without comparing the candidate to
  the prior release's configuration digest.
- Use a connection-only wake, then prove the exact running Container instance,
  before strict service-version and fixture acceptance.
- Keep the explicit `immediate` Container rollout strategy and retain the
  recovery ownership record only for interrupted non-atomic work.
- Allow future release identities to remain unique even if the historic ledger
  contains a published duplicate codename.

## Safety

The recovery still performs one explicitly authorized immutable-image restore,
does not retry an uncertain write, and releases its ownership record only after
the restored Worker and Container pass bounded read-only acceptance. Basket,
Auth0, and Nemlig-provider behavior are unchanged.
